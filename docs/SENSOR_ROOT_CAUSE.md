# 주택용 센서 값 누락 원인 조사

조사일: 2026-10-13

## 로컬 수정 반영

2026-10-13 후속 수정에서 주택용 `/my/charge/view/` 요청과 상세 파서를 추가하고 월별 차트 요청 범위를 24개월로 늘렸습니다. 검침·요금 상세·전월 및 전년동월 사용량을 기존 엔티티에 연결하며 이력에서도 전월·전년동월 값을 보충합니다. 상세 응답의 청구월을 확인하고 요청 실패 시 이력을 유지합니다. 주택용 센서 속성 `house_detail_status`로 상세 조회 결과를 확인할 수 있습니다.

아래 원인 조사는 커밋 `a8bb523`의 수정 전 동작을 기록한 내용입니다. Power Planner 항목은 후속 수정 범위에 포함하지 않았습니다. 상세 요금 제목과 값 형식은 공개 스키마 기반 합성 자료로 검증했으며 실계정 및 운영 HA 적용 검증은 아직 진행하지 않았습니다.

조사 기준: 통합 0.4.0, 커밋 `a8bb523`. 사용자 계약은 주택용 직접계약이며 운영 Home Assistant는 2026.10.1입니다. 실제 계정 인증 정보와 로그인된 파워플래너 화면에는 접근하지 않았습니다.

## 결론

현재 통합의 주택용 구현은 마이페이지의 월별 요약 차트와 제한된 Power Planner 응답만 가져옵니다. 한전ON의 주택용 상세 조회와 파워플래너 사이트 전체 조회 경로가 구현되어 있지 않습니다. 센서는 공통으로 34개를 생성하지만, 주택용에서 채워지지 않는 필드에 연결된 센서는 `unknown`이 됩니다.

이 때문에 웹에서 정보를 볼 수 있다는 사용자 설명과 통합에서 값이 없다는 현상이 함께 성립합니다. 서버 미제공 여부는 실제 응답을 확인해야 하며, 현재 진단 파일과 합성 응답으로 서버 미제공을 판정할 수 없습니다.

## 확인한 조회 경로 차이

| 정보 | 현재 통합 | 한전 공개 화면 정의 | 판정 |
| --- | --- | --- | --- |
| 주택용 청구 상세 | 조회하지 않음 | `/my/charge/view/` → `dma_charge`, `dlt_mny` 등 | 상세 요청 누락 확인 |
| 검침 지침·검침일 | 주택용 파서에서 채우지 않음 | `dma_charge.whmMtrAlw`, `bfrMtrAlw`, `gumchmDd` | 필드 매핑 누락 확인 |
| 전월·전년동월 사용량 | 주택용 파서에서 채우지 않음 | `dma_charge.befKwh`, `lastYearKwh` | 필드 매핑 누락 확인 |

주택용 상세 요청 `/my/charge/view/`는 통합의 `ALLOWED_PATHS`에도 없습니다. 단순한 화면 표시나 Home Assistant 버전 차이를 조사하기 전에 필요한 원본 조회가 빠져 있는 상태입니다.

`parse_house_bill()`은 월별 차트의 청구월, 기간, 사용량, 청구금액, 이력만 `KepcoBill`에 채웁니다. 기존 월별 이력이 있어도 전월·전년동월 사용량 단독 센서가 읽는 필드에는 이를 넣지 않습니다. 이 차이는 회귀 테스트로도 확인했습니다.

## 작년 월별 사용량의 누락

월별 센서는 현재 청구월을 기준으로 상대 월 `0`, `-1`, `-2`, `-12`, `-13`, `-14`를 읽습니다. 최근 13개월이 현재 월을 포함한다면 `-13`, `-14`는 범위 밖입니다. 한전ON의 주택용 상세 화면은 24개월을 요청하므로 화면과 통합의 조회 범위가 다릅니다.

실제 서버가 항상 정확히 13개월을 반환하는지, 명의변경 시점 때문에 더 적게 반환하는지는 확인하지 않았습니다. 작년 같은 달 슬롯 `-12`까지 없는 원인은 실제 응답의 월 목록을 비교해야 확정할 수 있습니다.

추가로 통합의 차트 요청은 `chgYmd`를 앞 6자리로 자릅니다. 공개 상세 화면은 전달받은 `chgYmd`를 그대로 사용합니다. 이 형식 차이는 확인했지만, 서버 응답에 미치는 영향은 검증하지 않았습니다.

## 한전ON과 파워플래너의 차이

현재 `BASE_URL`은 `https://online.kepco.co.kr`이고 통합 요청은 해당 호스트에 고정되어 있습니다. 사용자가 제공한 `https://pp.kepco.co.kr:8030/low/main/main.do`는 별도 사이트입니다. 로그인하지 않은 요청은 `/intro.do`로 이동했습니다.

공개 한전ON 주택용 상세 화면에도 파워플래너로 이동하는 SSO 흐름이 있습니다. `/keyCreate`에서 생성한 연결 정보를 사용해 파워플래너의 `/KEPCOSSO.do`로 이동하도록 되어 있습니다. 현재 통합에는 이 연결 흐름과 파워플래너 상세 API 조회가 없습니다. 파워플래너 사이트의 정보를 모두 한전ON `/my/memo/powerPlanner`가 반환한다고 가정할 근거는 없습니다.

한전ON의 공개 마이페이지 정의는 `F_AP_QT`를 당월 사용량으로 표시하지만, `PREDICT_TOT`는 예상 전기요금으로 정의합니다. 따라서 이 필드를 주택용 예상 사용량으로 바로 연결하면 단위가 잘못될 수 있습니다. 사용자에게 보이는 파워플래너 예상 사용량의 정확한 필드와 단위를 별도로 확인해야 합니다.

동일 건물·단지 평균 사용량 역시 현재 주택용 조회 경로에 매핑이 없습니다. 파워플래너에서 제공하는 비교 대상과 기존 아파트 센서의 비교 대상이 같은지는 로그인 후 화면·API를 확인해야 합니다.

## 진단과 재현 근거

제공된 진단 파일은 로드 성공, 마지막 갱신 성공, 청구 데이터 1건을 기록합니다. 이 성공 여부는 전체 34개 센서의 값이 채워졌음을 뜻하지 않습니다. `parsed_fields`는 dataclass 필드 목록이며 실제 값 존재 여부가 아닙니다.

저장소의 `house_main_chart.json`, `house_power_planner.json`을 기존 API 클라이언트와 센서 코드에 전달한 결과:

- 실제 호출 경로는 `/my/memo/mainChart`, `/my/memo/powerPlanner` 두 개입니다.
- 34개 중 22개 센서에 값이 없습니다.
- 현재 누적 사용량은 값이 있습니다.
- 응답 fixture에 `PREDICT_TOT` 값이 있어도 주택용 예측 센서는 `source_unit_unverified`로 값이 없습니다.

이 fixture는 저장소에 포함된 과거 검증 자료이며 현재 사용자 계정 응답은 아닙니다. 기존 합성 재현의 25개 누락과 이번 fixture 재현의 22개 누락은 입력 자료가 달라 발생한 차이입니다.

결과 파일은 Git에서 제외한 `sensor-reproduction.house-fixture.safe.json`, `sensor-reproduction.root-cause.safe.json`에 저장했습니다. 실제 사용량·청구금액과 인증 정보는 포함하지 않습니다. 실제 HA 상태 머신과 HACS 설치 과정은 이번 재현의 범위에 포함되지 않습니다.

## 수정에 필요한 범위

1. 주택용 상세 조회와 `dma_charge`·`dlt_mny` 파서를 추가하고 기존 센서 필드로 연결합니다. 상세 요금 제목, 숫자와 날짜 형식은 실계정 응답으로 확인해야 합니다.
2. 월별 이력 조회 범위를 상세 화면과 맞추고 월별 이력·상세 응답의 청구월을 일치시킵니다. 전월·전년동월 사용량과 이에 의존하는 CO₂ 추정 센서도 함께 확인합니다.
3. 파워플래너 로그인 후 화면의 예측 사용량과 비교 사용량 출처를 확인합니다. 기존 센서의 단위와 비교 대상이 일치하는 값만 연결합니다.
4. 주택용에서 아직 구현되지 않은 값, 서버가 값을 제공하지 않은 경우, 연결 실패를 진단에서 구분하도록 보완합니다.

원인 조사 단계에서는 운영 통합 코드를 변경하지 않았습니다. 이후 로컬 수정 내용은 문서 앞부분에 별도로 기록했습니다.
