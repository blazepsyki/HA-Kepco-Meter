# 한전ON Home Assistant 커스텀 통합

한전ON 개인(`INDI`) 계정의 아파트 단일·종합계약 및 주택용 직접계약 전기요금 조회를 Home Assistant 센서와 응답 액션으로 가져오는 비공식 커스텀 통합입니다. 기본 조회는 한전ON 청구·검침 페이지의 월별 데이터이며, Power Planner 홈페이지 연동을 켜면 지원되는 고객의 시간별 사용량과 예측값도 제공합니다.

Repository: https://github.com/1bobby-git/HA-Kepco-Meter

## 현재 범위

- 지원: 한전ON 개인 계정(`INDI`), 아파트 세대 단일·종합계약 및 주택용 직접계약 요금.
- 미지원: 법인 계정, 전기공사업체 계정, 인증서 로그인, OACX 간편인증 자동화, CAPTCHA/MFA 우회, CO2 실측값. 시간별 값은 홈페이지에 수집된 자료이며 즉시 갱신되는 전력 측정값은 아닙니다.
- 통신: `https://online.kepco.co.kr`와 선택 기능의 `https://pp.kepco.co.kr`에서 허용된 경로만 사용하며 TLS 검증을 유지합니다.
- 배포 버전: `v0.4.1`. 이 브랜치에는 미배포 Power Planner 연동이 포함되어 있습니다. 기본은 고객마다 6개 논리 기기와 34개 센서이며, 홈페이지 연동 고객은 9개 기기에 기존 추가 센서 5개와 A~C 센서 17개를 연결하여 총 56개 엔티티를 등록합니다. 신규 17개 중 7개는 기본 활성, 진단 1개와 비교 9개는 기본 비활성입니다.

## 설치

### HACS 커스텀 저장소

1. HACS > Integrations > 우측 메뉴 > Custom repositories.
2. 저장소 URL에 `https://github.com/1bobby-git/HA-Kepco-Meter` 입력.
3. Category는 Integration 선택.
4. `한전ON (KEPCO ON)` 설치 후 Home Assistant를 재시작.

### 수동 설치

`custom_components/kepco_on` 폴더를 Home Assistant 설정 디렉터리의 `/config/custom_components/kepco_on`에 복사한 뒤 Home Assistant를 재시작합니다. `/config`는 File editor 애드온, Samba share, SSH 애드온, 또는 호스트에 마운트된 설정 디렉터리로 접근할 수 있습니다. 재시작 후 통합 목록이 오래된 상태로 보이면 브라우저 캐시를 지우고 다시 열어 보세요.

## 설정

설정 > 기기 및 서비스 > 통합 추가 > KEPCO ON을 선택합니다.

1. 한전ON 아이디와 비밀번호를 입력합니다.
2. 자동 재인증이 필요하면 `비밀번호 저장`을 켭니다.
3. 조회할 고객을 선택합니다. 아파트/오피스텔은 아파트명·동·호를, 주택용 직접계약은 계약 유형과 마스킹된 고객번호를 표시합니다. 같은 계정에 지원하지 않는 계약(예: 일반용)이 함께 있으면 그 계약만 목록에서 제외합니다.

`비밀번호 저장`을 끄면 비밀번호는 저장하지 않습니다. 재시작/세션 복구를 위해 refresh token, 최소 세션 식별 정보와 한전ON 인증에 사용되는 `JSESSIONID`/`kepcoSSO` 쿠키만 private Home Assistant Store에 저장합니다. 쿠키는 한전 도메인·경로·만료 검증을 통과한 경우에만 보존하며, 요청 중 갱신된 값도 최신 스냅샷으로 다시 저장합니다. 저장된 서버 세션 자체가 만료되면 재인증이 필요할 수 있으며, `비밀번호 저장`을 켠 경우에는 자동 재로그인을 시도합니다. 비밀번호를 저장하지 않은 경우에는 조회 중 만료가 감지되면 재인증을 요청하기 전에 저장된 refresh token으로 세션 확인을 한 번 시도합니다.

이 통합은 Config Entry, Store, 백업을 자체 암호화하지 않습니다. 비밀번호 저장 여부와 관계없이 Home Assistant 호스트, `.storage`, 백업 파일을 비밀 저장소처럼 보호하세요.

## 생성되는 기기와 센서

선택한 고객마다 기본 6개 논리 기기와 총 34개 센서 엔티티를 등록합니다. Power Planner 홈페이지를 연동한 고객은 다음 분류의 9개 기기와 총 56개 엔티티를 등록합니다. 아파트는 기본 34개가 활성 상태이며 주택용 직접계약은 해당동·아파트 전체 비교 2개를 비활성화합니다. 한전ON에서 값이 제공되지 않으면 해당 엔티티는 `unknown`으로 표시될 수 있습니다.

통합 허브 제목은 `1001동 101호`(가상 예시)처럼 선택 세대 위치로 표시하고, 하위 기기 이름은 아래 분류 이름으로 표시합니다. 동·호의 앞자리 0은 표시 단계에서 제거합니다. 사용자가 설정 과정에서 별도 표시 이름을 입력한 경우에는 해당 이름을 유지합니다.

| 기기 | 기본 엔티티 수 | 홈페이지 연동 후 | 포함 정보 |
| --- | ---: | ---: | --- |
| 월별 사용량 | 6 | 7 | 청구월 이력, 달력 올해 사용량 |
| 검침 정보 | 5 | 5 | 검침일, 사용 기간, 당월·전월 지침 |
| 전기사용량·예측 | 7 | 11 | 청구 사용량, 현재·예측, 오늘·어제·최근 구간, 달력 이번 달 |
| 사용량 통계·수집 진단 | — | 4 | 오늘 최대·최소·평균 구간, 수집률 |
| 확정 전기요금 | 10 | 10 | 청구 상세, 할인, 세금, 청구금액 |
| 현재·예상 전기요금 | — | 4 | 홈페이지 현재·예상 요금과 누진단계 |
| 사용량 기간 비교 | — | 3 | 전년 같은 날짜 사용량·차이·변화율 |
| 이웃 전기사용량 비교 | 3 | 9 | 본인·동·단지, 지역·절약이웃 비교 |
| 온실가스 배출량 | 3 | 3 | 당월·전월·전년동월 추정 |

수량은 비활성 항목도 포함합니다. 홈페이지 전용 기기 3개는 연동한 고객에만 등록합니다. 계약별 제한과 사용자의 선택에 따라 실제 활성 엔티티 수는 달라집니다.

### 월별 사용량 · 6개

현재 청구월을 기준으로 최근 3개월과 전년 같은 기간 3개월을 함께 제공합니다. 엔티티의 고유 ID는 상대 월 위치를 사용하므로 청구월이 바뀌어도 엔티티가 새로 누적되지 않고 표시 이름만 갱신됩니다.

| 표시 예시 | 값 예시 |
| --- | ---: |
| 2025년 6월 | 399 kWh |
| 2026년 6월 | 371 kWh |
| 2025년 7월 | 459 kWh |
| 2026년 7월 | 406 kWh |
| 2025년 8월 | 612 kWh |
| 2026년 8월 | 573 kWh |

### 검침 정보 · 5개

| 센서 | 값 예시 |
| --- | ---: |
| 전기 사용 기간 시작일 | 2026-07-01 |
| 전기 사용 기간 종료일 | 2026-07-31 |
| 검침일 | 01 |
| 당월지침 | 23,139 kWh |
| 전월지침 | 22,566 kWh |

`검침일`, `전기 사용 기간 시작일`, `전기 사용 기간 종료일`은 이 기기의 `센서 정보` 영역에 표시하고, 지침 2개는 `센서` 영역에 표시합니다.

### 전기사용량·예측 · 기본 7개

| 센서 | 값 예시 |
| --- | ---: |
| 당월 사용량 | 573 kWh |
| 당월 세대 사용량 | 573 kWh |
| 당월 공용 사용량 | 0 kWh |
| 전월 사용량 | 406 kWh |
| 전년동월 사용량 | 612 kWh |
| 현재 검침기간 누적 사용량 | 246.80 kWh (종합계약 호환 예시) |
| 한전 예측 사용량 | 987.65 kWh (종합계약 호환 예시) |

한전ON이 `당월 세대 사용량`과 `당월 공용 사용량`을 모두 비워서 반환하면 전체 사용량을 세대 사용량으로, 공용 사용량을 `0 kWh`로 보정합니다. 한쪽 또는 양쪽의 실제 값이 있으면 한전ON 원본 값을 우선 사용하고 필요한 한쪽만 전체 사용량과의 차이로 계산합니다.

주택용 직접계약의 `전월 사용량`과 `전년동월 사용량`은 같은 월 청구 상세의 값을 우선 사용하고, 상세에 값이 없으면 `mainChart` 24개월 이력의 해당 월 값으로 채웁니다. 둘 다 없으면 `unknown`입니다.

아파트(종합계약)은 사용자 재현 보고에 따른 호환 프로필로 Power Planner의 `F_AP_QT`와 `PREDICT_TOT`를 각각 1000으로 나눠 기존 두 센서에 전달합니다. 이 단위 해석은 한전 공통 규격으로 검증되지 않았으며 `conversion_basis=user_reported_combined_contract`로 명시합니다. 다른 계약의 예측값 보류는 유지합니다. 값이 없는 필드만 `unknown`이고 실제 0은 유지됩니다.

### 확정 전기요금 · 10개

| 센서 | 값 예시 |
| --- | ---: |
| 전기요금 계 | 85,484 KRW |
| 전기요금 상세 기본요금 | 6,060 KRW |
| 전기요금 상세 전력량요금 | 87,402 KRW |
| 전기요금 상세 기후환경요금 | 5,157 KRW |
| 전기요금 상세 연료비조정요금 | 2,865 KRW |
| 전기요금 상세 출산가구할인요금 | -16,000 KRW |
| 부가가치세 | 8,548 KRW |
| 전력기금 | 2,300 KRW |
| 원단위절사금액 | 2 KRW |
| 청구금액 | 96,330 KRW |

Home Assistant 기기 화면은 기기 이름과 같은 일반 공백 접두어를 엔티티 이름에서 자동 생략할 수 있습니다. `v0.2.2`부터 전기요금 엔티티는 위 표의 전체 이름이 그대로 표시되도록 처리합니다.

금액 센서는 Home Assistant의 monetary device class 규칙에 맞춰 ISO 4217 통화 코드 `KRW`를 사용합니다. 위 기후환경요금 예시는 저장소의 한전ON 응답 샘플에 포함된 실제 값 `5,157원`을 기준으로 합니다.

출산가구 할인에 해당하지 않는 가구는 `전기요금 상세 출산가구할인요금` 엔티티를 개별적으로 끌 수 있습니다. 설정 > 기기 및 서비스 > KEPCO ON > 해당 가구의 확정 전기요금 기기에서 엔티티를 선택하고, 톱니바퀴 > 활성화 토글을 끈 뒤 업데이트합니다. [Home Assistant의 엔티티 활성화·비활성화 안내](https://www.home-assistant.io/common-tasks/general/#to-enable-or-disable-a-single-entity)를 참고하세요. 사용자가 끈 상태는 청구 갱신·통합 재로드·재시작 후에도 유지하며 다른 가구에는 영향을 주지 않습니다. 할인 센서를 끄더라도 확정 청구금액과 청구 상세 자료는 유지됩니다. 할인값의 누락이나 `0`만으로 할인 대상 여부를 판단하지 않으므로 자동으로 끄지는 않습니다. 다시 필요해지면 같은 설정에서 활성화합니다.

### 이웃 전기사용량 비교 · 3개

| 센서 | 값 예시 |
| --- | ---: |
| 고객님 | 573 kWh |
| 해당동 | 363 kWh |
| 아파트 전체 | 284 kWh |

비교 항목은 한전ON의 계약 유형으로 구분합니다. `주택용`으로 시작하는 계약은 주택용 직접계약으로 처리하며, 건물 이름이나 주소로 아파트 여부를 추측하지 않습니다.

| 비교 항목 | 아파트 계약 | 주택용 직접계약 |
| --- | --- | --- |
| 고객님 | 기본 활성 | 기본 활성 |
| 해당동·아파트 전체 | 기본 활성 | 계약에 해당하지 않아 비활성 |
| Power Planner 지역 평균·절약이웃 사용량과 요금, 사용량·요금 순위 6개 | 현재 지원 프로필에 해당하지 않아 비활성 | 선택 활성화 가능, 기본 비활성 |
| Power Planner 전년 같은 날짜 사용량·차이·변화율 | 선택 활성화 가능, 기본 비활성 | 선택 활성화 가능, 기본 비활성 |

업데이트 전에 켜져 있던 비대상 항목도 통합 로드 때 비활성화하며 엔티티 ID는 유지합니다. 사용자가 직접 끈 상태는 유지합니다. 비대상 항목을 수동으로 켜더라도 값은 `unknown`, `data_status`는 `unsupported_profile`이며 아파트 계약의 지역 비교 요청은 실행하지 않습니다. Power Planner 지역 비교는 현재 주택용 계약을 대상으로 검증한 지원 범위이며, 아파트 계약에서 홈페이지 자체가 자료를 제공하지 않는다는 뜻은 아닙니다.

### 온실가스 배출량 · 3개

| 센서 | 값 예시 |
| --- | ---: |
| 당월 배출량 | 263 kg CO₂ |
| 전월 배출량 | 186 kg CO₂ |
| 전년동월 배출량 | 281 kg CO₂ |

온실가스 값은 한전ON 실측값이 아니라 각 전기사용량에 설정된 환산계수를 곱한 로컬 추정값입니다. 기본 환산계수는 `0.459 kg CO₂/kWh`입니다.

엔티티 ID는 Home Assistant가 설치 환경의 이름 충돌 상태에 따라 정합니다. 고객별 고유 ID에는 원본 고객번호나 계약번호 대신 계정·고객 정보로 만든 안정 해시를 사용합니다.

## 에너지 대시보드

Energy Dashboard에는 `당월지침` 센서를 전력 사용량 소스로 추가합니다. 이 센서는 누적 검침값이며 `total_increasing` 상태 클래스를 사용합니다. 월별 사용량과 비교 사용량 센서는 한 달 단위 값이므로 누적 소스로 사용하지 않습니다.

## 옵션, 업그레이드, 재인증, 재구성

### Power Planner 홈페이지 연동 · 선택 기능

통합 옵션에서 `Power Planner 홈페이지 연동`을 켜면 같은 한전 계정으로 [Power Planner](https://pp.kepco.co.kr/intro.do)에 별도 로그인합니다. 기본값은 꺼짐입니다. 홈페이지의 현재 주 고객번호가 한전ON에서 선택한 세대 계약번호와 정확히 일치하고, 계량 주기가 60분인 경우에만 활성화합니다. 고객 전환이나 15분 계량 프로필은 아직 지원하지 않습니다. 다른 선택 고객은 기존 한전ON 조회를 계속 사용합니다.

옵션에는 별도의 비밀번호 입력 칸이 없습니다. 기존 한전ON의 저장 비밀번호 또는 유효한 Power Planner 세션을 사용합니다. 처음 연결하거나 세션이 만료되어 별도 로그인이 필요한 경우에만 인증 화면을 표시합니다. 이때 입력한 비밀번호는 로그인에만 사용하고 옵션이나 Config Entry에 저장하지 않습니다. Power Planner의 `JSESSIONID`만 한전ON과 분리된 Home Assistant Store에 저장합니다. 세션이 만료되면 저장 비밀번호가 있는 경우 한 번 재로그인하며, 없는 경우 복구 알림을 표시합니다. 이때 통합 옵션을 저장하면 필요한 인증 화면으로 이어집니다.

| 센서 | 동작 | 단위 |
| --- | --- | --- |
| 현재 검침기간 누적 사용량 | 기존 엔티티를 유지하고 홈페이지 값으로 갱신 | kWh |
| 한전 예측 사용량 | 기존 엔티티를 유지하고 홈페이지 값으로 갱신 | kWh |
| 오늘 사용량 | 새 센서. 한국 시간 오늘의 수집된 시간 구간 합계 | kWh |
| 어제 사용량 | 새 센서. 어제의 24개 구간이 유효할 때 제공 | kWh |
| 최근 수집 구간 사용량 | 새 센서. 오늘의 가장 최근 유효한 60분 구간 | kWh |
| 현재 검침기간 요금 | 새 센서. 홈페이지가 산정한 현재 기간 금액 | KRW |
| 현재 검침기간 예상 요금 | 새 센서. 홈페이지의 예측 금액 | KRW |

사용량은 홈페이지의 kWh 값을 그대로 사용합니다. 기존 한전ON 종합계약 호환 처리의 1000 나눗셈을 이 경로에 적용하지 않습니다. 한전ON의 월별 청구액·청구 기간·요금 상세와 응답 액션은 계속 청구 데이터를 사용합니다. 현재·예측 전기요금은 확정 청구금액과 다른 값입니다.

세션 유지 요청은 20분마다, 데이터 조회는 1시간마다 실행합니다. 이는 통합의 조회 간격이며 한전 서버의 수집 지연을 보장하지 않습니다. 누락 표시가 있는 구간의 숫자는 사용하지 않고, 유효한 실제 0은 유지합니다. 오늘의 일부 구간만 수집되면 `data_status=partial`, 어제가 불완전하면 `unknown`과 `data_status=incomplete`로 표시합니다. 연결·인증 실패도 Power Planner 센서의 `unknown`과 상태 속성으로 알립니다. 한전ON 청구 조회는 별도로 계속됩니다.

기간값은 각 센서의 `usage_period_start`·`usage_period_end`·`reference_date`, 일별 값은 `calendar_date`·`valid_intervals` 속성에서 확인할 수 있습니다. 실제 마지막 계량 시각은 아직 검증하지 못해 별도 센서로 제공하지 않습니다. 새 사용량 센서는 일별·구간별 값이거나 검침기간에 초기화되는 값이므로 Energy Dashboard의 누적 사용량 소스로 등록하지 않습니다.

연동을 끄면 기존 두 엔티티는 한전ON 조회로 돌아가고, 기본 활성인 추가 엔티티는 통합에 의해 비활성화됩니다. 기본 비활성인 진단·비교 엔티티는 사용자가 선택한 registry 활성 상태를 유지하며 센서 제공과 조회를 중지합니다. 사용자가 설정한 이름과 직접 비활성화한 상태는 유지합니다. 저장한 Power Planner 세션은 연동 해제 또는 통합 항목 삭제 시 제거합니다.

#### A~C 추가 센서

| 범위 | 추가 센서 | 기본 상태 |
| --- | --- | --- |
| 구간 통계 | 오늘 최대·최소·평균 구간 사용량 | 활성 |
| 수집 진단 | 오늘 구간 수집률 | 비활성·진단 |
| 누진 정보 | 현재·예상 누진단계 | 활성 |
| 달력 집계 | 달력 이번 달·올해 사용량 | 활성 |
| 날짜 비교 | 전일 기준 전년 같은 날짜 사용량, 전일 전년 대비 차이·변화율 | 비활성 |
| 홈페이지 기본 지역 비교 | 지역 비교 평균·절약이웃 사용량과 요금, 사용량·요금 순위 백분율 | 비활성 |

통계는 `NO_DATA_YN=N`인 유효 구간에서 계산합니다. 실제 0은 포함하고 미수집 구간은 제외합니다. 수집률은 하루 24개 구간 대비 수집 진행률이며 현재 시각까지의 통신 성공률과는 다릅니다. 유효 구간이 없으면 통계는 `unknown`, 수집률은 `0%`입니다. 응답 형식 자체가 잘못되면 수집률도 `unknown`입니다.

달력 월 집계는 홈페이지의 `MONTH` 모드를 사용합니다. 홈페이지의 월별·연간 화면에 표시되는 월은 검침기간 기준이므로, 달력 올해 값은 올해의 달력 월 자료를 합산합니다. 현재 일·월·연도는 `partial`로 표시할 수 있으며 미래 날짜와 미제공 자료를 0으로 합산하지 않습니다. 달력 월은 1시간, 달력 올해는 6시간마다 갱신합니다. 자료의 `period_kind`, 기간, `reference_date`, `last_successful_fetch` 속성에서 기준과 조회시각을 확인할 수 있습니다.

누진단계는 서버의 현재·예상 단계가 확인된 주택용 계약에서 제공합니다. 고객·기간·단계 코드가 맞지 않으면 해당 센서만 `unknown`입니다. 진행 중인 기간의 단계와 예상 단계는 확정 청구 정보와 구분합니다.

날짜 비교는 일부 수집된 오늘과 전년의 하루 전체를 비교하지 않도록 완결된 전일 자료를 사용합니다. 기준일은 `calendar_date`, 전년의 대응일은 `comparison_date`에 표시합니다. 윤일에 대응하는 날짜가 없으면 `unknown`입니다. 전년 값이 실제 0이면 차이는 제공하고 변화율은 `baseline_zero` 상태로 보류합니다.

지역 비교는 홈페이지가 처음 조회할 때 쓰는 기본 지역 필터·월을 그대로 사용합니다. `comparison_scope=portal_default_region`, `comparison_period`로 기준을 표시하고 원본 지역 코드·이름은 속성에 넣지 않습니다. 순위는 홈페이지의 ‘내순위(상위%)’ 표시값이며 좋은/나쁜 소비 등급으로 해석하지 않습니다. 사용량 행과 요금 행의 같은 필드 이름을 각각 kWh·KRW로 분리합니다.

비교 센서는 설정 > 기기 및 서비스 > 엔티티에서 해당 계약에 지원되는 항목을 활성화해 사용합니다. 지원되는 관련 센서가 하나라도 활성화됐을 때만 해당 자료를 조회하며 다음 20분 갱신에서 첫 조회가 실행됩니다. 지역 비교는 1일 간격으로 갱신합니다. 비교집단을 검증할 수 없으면 `comparison_scope_unverified`, 기간이 맞지 않으면 `period_mismatch`로 표시합니다. 새 자료의 조회 실패는 해당 소스만 보류하며 정상 스마트뷰·구간 값과 한전ON 청구 조회는 유지합니다.

### 한전ON 옵션과 설정 변경

옵션에서 조정할 수 있는 값은 한전ON 조회 주기, 온실가스 환산계수, 사용량 이력 응답 길이와 Power Planner 연동 여부입니다. 한전ON 조회 주기는 1·3·6·12·24시간 중 선택하며 기본값은 6시간입니다. 환산계수는 0보다 크고 10 이하이며 기본값은 `0.459`입니다. 이력 응답 길이는 1~24개월이며 기본값은 12개월입니다.

기존 `검침/전기사용량` 기기는 같은 기기 ID의 `검침 정보`로, `전기요금`은 같은 기기 ID의 `확정 전기요금`으로 정리합니다. 월별·이웃·온실가스 기기 ID도 유지합니다. 사용자가 지정한 기존 기기 이름은 유지하므로 사용자 환경에서는 새 기본 이름과 다르게 보일 수 있습니다. 새 기기는 원래 기기의 영역·라벨·기기 비활성 상태를 이어받고, 이미 존재하는 새 기기의 설정은 덮어쓰지 않습니다. 이동한 센서의 기존 영역과 새 기기의 영역이 다르면 센서에 기존 영역을 유지합니다.

기기를 대상으로 한 자동화는 분리된 센서까지 포함하지 않을 수 있습니다. 기존 검침/전기사용량·전기요금 기기를 대상으로 사용량·예측 기능을 구성했다면 새 기기 또는 해당 엔티티로 대상을 갱신하세요. 엔티티 ID를 대상으로 한 자동화는 기존 ID를 계속 사용합니다. 홈페이지 연동을 끄면 전용 센서의 기기 연결을 해제하고 빈 전용 기기를 정리하며, 다른 플랫폼의 엔티티나 다른 통합이 사용하는 기기는 보존합니다.

업데이트 후 Home Assistant Core를 완전히 재시작하세요. 기존 엔티티 ID와 unique ID는 유지하며 기기 연결은 새 분류로 옮깁니다. 이전 설정의 상세·CO₂ 생성 토글은 마이그레이션에서 정리하며, 사용자가 직접 비활성화한 엔티티는 유지합니다. 쿠키 없는 이전 세션은 저장 비밀번호가 있으면 재로그인하고, 없으면 재인증을 요청합니다. 버전별 변경은 [변경 이력](CHANGELOG.md)을 참고하세요.

재인증은 기존 계정의 비밀번호만 다시 받습니다. 다른 한전ON 계정으로 로그인되면 항목 업데이트가 거절됩니다. 재인증은 고객 선택을 바꾸지 않습니다. 설정된 고객이 계정에서 확인되지 않으면 항목을 그대로 둔 채 중단하므로, 재구성에서 고객 선택을 정리한 뒤 다시 재인증하세요. 고객 목록 응답에 형식이 잘못된 행이 있어 설정된 고객이 보이지 않으면 고객 목록 응답 변경으로 중단합니다. 이때는 고객을 지우지 말고 통합을 업데이트한 뒤 다시 시도하세요. 한전ON이 회원 이름을 다르게 반환해 내부 고객 키가 달라져도 고객번호와 계약번호가 같으면 기존 키와 고유 ID를 유지합니다.

재구성은 선택 고객을 갱신합니다. 통합이 로드된 상태면 한전ON에서 고객 목록을 새로 받아옵니다. 통합이 로드되지 않았거나, 조회가 인증 오류로 멈췄거나, 새로 고침이 인증 오류로 실패하면 다시 로그인하지 않고 저장된 고객 목록으로 선택 화면을 엽니다. 연결 오류처럼 일시적인 실패는 오류를 표시하며 다시 시도할 수 있습니다. 선택에서 빠진 고객의 엔티티와 이 통합만 소유한 논리 기기는 정리됩니다. 남은 기기가 있으면 기기 화면의 삭제 메뉴로 지울 수 있으며, 선택된 고객의 기기는 삭제가 거절됩니다.

## 응답 액션

`kepco_on.get_monthly_bill`은 한 고객의 청구 상세를 반환합니다. 아파트/오피스텔과 주택용 직접계약 모두 지정한 월을 조회합니다. 주택용은 `mainChart` 이력에서 요청한 월을 고른 뒤 같은 월의 청구 상세를 결합합니다. 해당 월이 이력에 없으면 조회 오류를 반환합니다.

```yaml
action: kepco_on.get_monthly_bill
data:
  config_entry_id: !secret kepco_on_config_entry_id
  customer_id: !secret kepco_on_customer_id
  month: "202608"
response_variable: kepco_bill
```

`kepco_on.get_usage_history`는 선택 고객의 월별 사용량 이력을 반환합니다. `month`를 비우면 현재 코디네이터가 가진 최신 청구 데이터를 우선 사용합니다. 각 이력 항목은 `month`·`usage_kwh`를 포함하고, 한전ON 응답에 해당 월 청구액이 있으면 `amount_krw`도 함께 반환합니다. 같은 값은 `월별 사용량` 센서의 `amount_krw` 속성으로도 노출됩니다.

```yaml
action: kepco_on.get_usage_history
data:
  config_entry_id: !secret kepco_on_config_entry_id
  customer_id: !secret kepco_on_customer_id
response_variable: kepco_history
```

`config_entry_id`는 개발자 도구 > 액션 또는 자동화 시각 편집기에서 `config_entry_id` 선택기를 열고 KEPCO ON 항목을 선택하면 Home Assistant가 채웁니다. 수동 YAML에 넣어야 할 때는 선택기로 항목을 고른 뒤 YAML 보기로 전환해 생성된 ID를 복사하세요.

`customer_id`는 원본 한전 고객번호가 아니라 통합이 생성한 64자 안정 해시 키입니다. 가장 신뢰할 수 있는 확인 경로는 설정 > 기기 및 서비스 > KEPCO ON 항목 > 점 세 개 메뉴 > 진단 다운로드에서 진단 파일을 내려받은 뒤 `selected_customer_ids` 값을 복사하는 것입니다. 이 값은 응답 액션에 필요한 안전 식별자이며 원본 한전 고객번호나 계약번호가 아닙니다. 그래도 공개 이슈나 자동화 예제에 올릴 필요는 없습니다. 진단 다운로드가 어려운 환경에서는 설정 > 기기 및 서비스 > 엔티티에서 KEPCO ON 센서 엔티티 설정을 열고 entity registry의 unique ID 앞 64자를 확인하는 방법을 대안으로 사용할 수 있습니다.

## 자동화 예시

```yaml
alias: 한전ON 월 사용량 알림
triggers:
  - trigger: time
    at: "09:00:00"
conditions:
  - condition: template
    value_template: "{{ now().day == 1 }}"
actions:
  - action: kepco_on.get_usage_history
    data:
      config_entry_id: !secret kepco_on_config_entry_id
      customer_id: !secret kepco_on_customer_id
    response_variable: usage_history
  - action: notify.mobile_app_phone
    data:
      message: "한전ON 최근 이력: {{ usage_history.history | count }}개월"
```

## 문제 해결

### 일시 연결 오류와 자동 복구

한전ON 청구 조회에서 `temporary connection failure`가 발생하면 통합을 수동 재로드하지 않아도 1·2·4·8·15분 간격으로 재시도합니다. 이후에도 실패하면 15분 간격을 유지하며, 정상화되면 설정한 한전ON 조회 주기로 돌아갑니다. 각 요청의 기존 최대 3회 재시도 후에도 실패했을 때 적용하는 갱신 정책입니다. 일부 고객만 실패하면 정상 조회된 고객의 새 값을 제공하고 실패한 고객만 사용할 수 없는 상태로 표시합니다. 실패한 값을 `0`으로 바꾸거나 과거 값을 최신 정상값으로 표시하지 않습니다.

429 요청 제한은 일반 연결 실패와 구분합니다. 같은 갱신의 나머지 고객 조회를 중지하고 20·40·60분으로 대기 시간을 늘립니다. 서버가 더 긴 `Retry-After`를 보내면 최대 24시간 범위에서 그 값을 반영합니다. 최초 설정 실패는 HA의 설정 재시도 기능을 사용합니다. 자동 갱신을 사용자가 껐거나 활성 센서가 없으면 주기적 재시도를 하지 않습니다. 인증 만료는 저장 비밀번호로 기존 자동 재로그인을 한 번 시도하며, 비밀번호가 없거나 인증이 거절되면 사용자 재인증이 필요합니다.

`device_registry.async_get_device` 경고는 config entry를 지정하는 기기 조회 API로 수정했습니다. `closes the Home Assistant aiohttp session` 경고는 쿠키 세션의 정리 방식을 `detach()`로 수정했습니다. 이전 코드가 이미 HA 공유 연결 풀을 닫았을 수 있으므로 이 수정본을 설치할 때는 통합 재로드에 그치지 않고 **Home Assistant Core를 한 번 완전히 재시작**하세요. 이후 일시 연결 실패는 위 정책으로 복구합니다. 과거의 일반 연결 오류 로그만으로는 타임아웃·네트워크 장애·서버 오류·429 중 어느 원인이었는지 확정할 수 없습니다.

### 기타 오류

- 로그인 실패: 한전ON 웹에서 같은 계정으로 직접 로그인되는지 확인합니다. CAPTCHA, MFA, OACX 등 조건부 챌린지가 나오면 이 통합은 우회하지 않습니다.
- 세션 만료/복원 실패: `v0.3.11`은 refresh token과 허용된 `JSESSIONID`/`kepcoSSO` 인증 쿠키를 함께 복원합니다. `v0.3.9`에서 넘어온 쿠키 없는 세션은 비밀번호 저장 시 자동 재로그인하고, 비밀번호가 없으면 기존 항목을 유지한 채 재인증을 요청합니다.
- 고객 없음: 이 통합은 개인 계정의 아파트 세대 계약과 주택용 직접계약만 지원합니다. 다른 계약 유형은 고객 목록에서 제외됩니다.
- 일부 세대만 unavailable: 한 세대의 청구 조회 실패는 다른 세대 센서와 분리됩니다.
- 월 조회 실패: 응답 액션의 `month`는 `YYYYMM`이고 현재월보다 미래이거나 최근 24개월 범위 밖이면 거절됩니다.
- 프로토콜 변경 수리 이슈: 한전ON 응답 구조가 바뀌면 원본 응답 없이 안전한 오류 분류만 수리 이슈로 표시됩니다.
- `login bootstrap content type changed`가 보이는 경우: 기존 `v0.1.0` 또는 오래된 설치본에서 로그인 bootstrap 응답을 지나치게 엄격하게 검사했을 수 있습니다. HACS에서 `v0.1.1` 이상으로 업데이트한 뒤 Home Assistant를 완전히 재시작하고, 설치된 통합 버전이 `0.1.1` 이상인지 확인한 다음 다시 설정하세요.

설치된 매니페스트 버전 확인:

```bash
cat /config/custom_components/kepco_on/manifest.json
```

과거 로그인 bootstrap 오류 검색:

```bash
grep -F "login bootstrap content type changed" /config/home-assistant.log* 2>/dev/null
```

문제가 계속되면 공개 이슈에는 비밀번호, 쿠키, 토큰, 원본 고객번호, 계약번호, HAR, raw capture를 올리지 마세요. 공유 가능한 자료는 검토 후 민감값을 지운 로그와 `login-schema.safe.json`뿐입니다.

## 주택용 청구 상세

주택용 직접계약은 월별 이력과 같은 청구월의 상세 응답을 결합합니다. 상세에 값이 있으면 전기요금 항목, 검침지침·검침일, 전월·전년동월 사용량과 기존 CO₂ 추정 센서에 반영합니다. 이웃 비교와 세대·공용 사용량 등 주택 응답에 없는 값은 채우지 않습니다.

상세 조회가 실패해도 월별 이력과 청구액은 유지하며, 주택용 센서의 `house_detail_status`에서 `ok`, `connection_error`, `rate_limited`, `invalid_response`를 확인할 수 있습니다. 인증 만료는 재인증 흐름으로 전달됩니다. 과거월 조회에는 현재 검침기간의 사용량을 붙이지 않습니다.

## Power Planner 상태 확인

홈페이지 연동의 `오늘 사용량` 센서는 개발자 도구 > 상태에서 찾아 속성의 `data_status`를 확인합니다. HA 버전에 따라 개발자 도구가 설정 > 도구에 표시될 수 있습니다. `partial`은 오늘의 일부 시간 구간만 수집됐다는 뜻이며 정상일 수 있습니다. `valid_intervals`는 유효한 구간 수, `calendar_date`는 조회한 한국 날짜입니다. 하루 전체가 수집되면 `ok`, 유효한 구간이 없으면 `no_data`입니다.

한전ON 내부 Power Planner 조회에서는 청구 조회가 정상이고 부가 사용량만 없으면 센서가 `unknown`으로 표시되며 진단 속성은 유지됩니다. 청구 조회 자체가 실패하거나 청구 스냅샷이 없으면 `unavailable`입니다.

| 상태 | 의미 |
| --- | --- |
| `ok` | 정상값 제공. 실제 0도 포함 |
| `no_data` | 유효한 값이 제공되지 않음. 반환 코드만으로 원인을 확정하지 않음 |
| `source_unit_unverified` | 예측 필드의 에너지 단위를 확인하지 못해 표시 보류 |
| `connection_error`, `rate_limited`, `invalid_response` | 부가 요청의 연결·제한·형식 오류 |

개발자 도구 > 템플릿에서 다음과 같이 확인할 수 있습니다.

```jinja
{% for s in states.sensor
   if s.attributes.get('source_field') in ['F_AP_QT', 'PREDICT_TOT'] %}
{{ s.name }}: {{ s.state }}
버전: {{ s.attributes.get('integration_version') }}
상태: {{ s.attributes.get('data_status') }}
반환 코드: {{ s.attributes.get('provider_return_code') }}
설명: {{ s.attributes.get('data_status_message') }}
변환 계수: {{ s.attributes.get('value_divisor') }}
{% else %}
대상 센서가 없습니다. 기기 화면에서 엔티티 상태를 확인하세요.
{% endfor %}
```

## 삭제

설정 > 기기 및 서비스에서 KEPCO ON 항목을 삭제합니다. 이 통합의 세션 Store와 복구 안내도 정리됩니다. 수동 설치를 제거하려면 `custom_components/kepco_on` 폴더를 삭제하고 Home Assistant를 재시작합니다.
